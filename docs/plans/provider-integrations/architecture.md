# Provider integrations: architecture and migration specification

**Implements:** [requirements](requirements.md). **Decision:** [approved design](../2026-09-21-provider-integrations-design.md). All new names below are design targets for implementation agents to reconcile with the actual code before editing.

## 1. Hexagonal ownership

Keep provider choice and health/configuration at the adapter edge. Application services express business operations through existing ports; domain types contain no Quarkus, Jakarta, SDK, or HTTP types. No module reads another module's tables. A platform-owned selection repository exposes an input port to payment, media, notifications, and identity. A super-admin operational use case changes selection, checks provider readiness, and writes an audit entry. The readiness check may be a platform SPI implemented by provider adapters; it must not put SDK types or secrets in platform domain objects.

Do **not** represent a provider as a mere boolean `FeatureKey`. Existing `PSP_REDDE` defaults to sandbox and `FeatureFlagsAdapter.isEnabled` fails open when a row is absent; these are unsafe semantics for a production gateway selection. Per-rail flags remain independent. A migration plan must explicitly retire or adapt `PSP_REDDE`, never leave two controls that disagree. A provider selection is a small closed enum/code set, with an explicit `disabled` state for payment.

| Capability | Port and owner | Adapters | Persist selection on |
| --- | --- | --- | --- |
| Object storage | `media.ObjectStorePort` + `UrlSignerPort` | Existing S3 adapter configured for MinIO or S4; provider-aware client registry | Media asset/location before upload; separate migration progress outside the domain asset if needed. |
| Charges and payouts | `payments.PaymentGateway` | Existing sandbox and Redde adapters, routed by recorded vendor | `payment_intent.gateway_vendor`, `payout_txn.gateway_vendor` before external initiation. |
| Notification email | `notifications.Mailer` | Existing SMTP, new Resend | `delivery_attempt.provider_code` on enqueue. |
| Identity email | `identity.Mailer` | Compatibility adapter to shared transactional email delivery; SMTP/Resend transport | The password-reset send command at creation; if queued, persist provider with attempt. |
| SMS | `notifications.SmsSender` | Existing capture sender, new FROG | `delivery_attempt.provider_code` on enqueue. |

## 2. Selection and operation protocol

Suggested operational API: `GET /v1/admin/provider-config` returns provider codes and safe readiness/status; `PUT /v1/admin/provider-config/{capability}` accepts `{ "provider": "...", "expectedVersion": n }`. This endpoint is **additive** and must be specified in [API-CONTRACT.md](../../../API-CONTRACT.md) and contract tests before implementation. It requires super-admin, optimistic version checking, and one audit entry per successful change. Never return endpoint credentials, key fragments, or webhook secrets. A simultaneous update with a stale version returns a conflict. A failed readiness check leaves the previous selection unchanged. No frontend administration UI is required for the first release; an authenticated operations client can use the endpoint.

Suggested `provider_selection` fields: `capability` primary key, `provider_code`, `version`, `updated_at`, `updated_by`. Valid codes are closed per capability. The selected provider is read at creation time, and the operation stores that code before its external side effect. The two actions need a durable transition protocol: commit a pending operation with its provider/idempotency reference, then dispatch; an uncertain response is reconciled with the **recorded** provider. Do not hold a database transaction open over a remote request where the current application service already avoids that pattern. Preserve existing charge and payout idempotency keys and ledger guards.

If the operator changes a selection while an operation is being created, the operation may take either the old or new value, but its persisted provider must match the adapter that receives the request. Test the race. An operator's `disabled` selection rejects later creation; it does not disable provider-specific callback routes, recon jobs, or delivery retries already enqueued. Expose an explicit per-capability pause only if business semantics require stopping existing retries too; this is outside this phase.

## 3. Payment details

`payment_intent.provider` is a rail, not the gateway. Add a separate gateway vendor value to the [entity](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/out/persistence/PaymentIntentEntity.java), [domain aggregate](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/domain/PaymentIntent.java), and mapper. Add equivalent vendor identity to [payout_txn](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/out/persistence/PayoutTxnEntity.java) and the payout domain/repository path. Keep public payment response shapes unless the contract explicitly needs an additive field. Ensure the selected vendor is determined once before `supportsDirectCharge`, `initiate`, or `initiateCheckout`; all those calls must use the same adapter. The same applies to `confirmsDisbursementAsync` and `disburse` for a payout.

Change [PaymentGatewayRouter](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/out/integration/PaymentGatewayRouter.java) so creation uses current selection and post-creation methods use stored vendor. This may require an internal port signature or a vendor-bound gateway handle; do not infer vendor from `providerRef` text. [PaymentReconJob](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/in/job/PaymentReconJob.java), [PayoutReconJob](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/in/job/PayoutReconJob.java), [PaymentWebhookResource](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/in/rest/PaymentWebhookResource.java), receipt/cashout handlers, and payment settlement paths must be traced as one graph. A Redde callback identifies a Redde transaction but cannot settle a row whose recorded gateway vendor is sandbox/unknown. Its payload is a hint; authenticated Redde status determines a terminal result. Preserve ownership-on-confirmed-settlement, refund clawback, balanced ledger, and payout reservation behavior.

Preexisting rows need an evidence-based backfill: inspect existing payment/payout references, callback/event history, deployment records, and active nonterminal counts. Mark ambiguous nonterminal rows for manual reconciliation; do not assign their vendor from the flag's current value. Historical terminal rows can receive a documented legacy code if no further provider I/O is possible. A migration must not silently relabel ambiguous pending work.

Production `sandbox` must fail activation validation. When payment selection is `disabled`, [`GET /v1/payments/providers`](../../../backend/src/main/java/org/shakvilla/beatzmedia/payments/adapter/in/rest/PaymentProvidersResource.java) reports no chargeable methods and initiation returns the existing stable provider-disabled error or an additive contract error agreed before coding. Revisit the current [checkout route](../../../Frontend/src/routes/checkout.index.tsx), [commerce API query](../../../Frontend/src/lib/api/queries/commerce.ts), and [API contract](../../../API-CONTRACT.md) together: a non-null `checkoutUrl` redirects to Redde but does not itself mark the order paid. The browser returns to a status/receipt poll driven by server settlement.

## 4. Media storage and migration

The [S3 client producer](../../../backend/src/main/java/org/shakvilla/beatzmedia/media/adapter/out/integration/S3ClientProducer.java) hardcodes signing region `us-east-1`; replace this with provider-specific region and endpoint configuration. Keep an explicit browser-reachable presign endpoint because rewriting a signed URL's host invalidates SigV4. The [object adapter](../../../backend/src/main/java/org/shakvilla/beatzmedia/media/adapter/out/integration/S3ObjectStoreAdapter.java) and [transcoder](../../../backend/src/main/java/org/shakvilla/beatzmedia/media/adapter/out/integration/FfmpegAudioTranscoderAdapter.java) must receive the correct store for each asset; direct injected `S3Client` users such as the [artwork processor](../../../backend/src/main/java/org/shakvilla/beatzmedia/media/adapter/out/integration/ImageArtworkProcessorAdapter.java) must be included in the refactor. Do not change only the public `ObjectStorePort` adapter and leave transcode/artwork reads on MinIO.

Object location is `{ storeCode, originalBucket, originalKey, deliveryBucket, renditionKeys }`, or an equivalent durable representation. Preserve the current stable public image URL route: [MediaImageResource](../../../backend/src/main/java/org/shakvilla/beatzmedia/media/adapter/in/rest/MediaImageResource.java) reads the recorded location. A migration worker copies every referenced object, verifies length and a trustworthy content hash where available (S3 ETag alone is not a universal checksum), records a durable migration status, then atomically switches the asset location. During copy, reads use source location; failed copy stays on source. Avoid split locations within one asset unless the model explicitly represents each object separately. Keep a rollback manifest and source objects until the retention decision is approved.

MEGA S4 advertises path-style S3 requests and SigV4 presigned URLs but excludes presigned POST and some checksum headers. Exercise the *actual* AWS SDK version in this repo against S4 before changing checksum options. Verify HEAD, GET, PUT, DELETE, range GET, signed browser GET, expiry, CORS if cross-origin browser delivery is used, 500 MB upload, transformed image, full audio, and the physical 30-second preview. Do not make source originals public. See [S4 coverage](https://github.com/meganz/s4-specs/blob/main/README.md).

## 5. Resend email

Maintain one transactional message model with recipient, subject, text/HTML body, stable operation ID, and provider selection. The existing [`notifications.EmailMessage`](../../../backend/src/main/java/org/shakvilla/beatzmedia/notifications/application/port/out/EmailMessage.java) already supplies an idempotency key. Pass it to Resend and persist Resend's returned message ID without treating acceptance as delivery. In the notification path, [DeliveryAttemptService](../../../backend/src/main/java/org/shakvilla/beatzmedia/notifications/application/service/DeliveryAttemptService.java) owns retry state; it selects the provider when creating the attempt, then uses that same provider on every retry. Keep Mailpit for local/test and use provider fixtures for failure classification. Do not log recipients, API keys, or raw password-reset links.

Identity's [password reset service](../../../backend/src/main/java/org/shakvilla/beatzmedia/identity/application/service/RequestPasswordResetService.java) currently calls a separate mailer directly. Connect it to the same selected transport through an input port or shared application service, preserving module boundaries; notifications must not read identity tables. Decide explicitly whether password-reset delivery is queued or synchronous; either way, each newly issued token has its own stable send ID and the send result cannot reveal whether an account exists. If Resend webhooks are enabled, verify the raw payload and signature, persist event IDs for deduplication, and map accepted/delivered/bounced/complained without allowing an older event to overwrite a newer terminal state. See [Resend webhook verification](https://resend.com/changelog/managing-webhooks-via-api).

## 6. FROG SMS

The [generic HTTP sender](../../../backend/src/main/java/org/shakvilla/beatzmedia/notifications/adapter/out/integration/HttpSmsSender.java) is for the capture stub. FROG needs a dedicated adapter, not an endpoint substitution: headers `API-KEY` and `USERNAME`, JSON with approved `senderid`, `destinations:[{destination,msgid}]`, `message`, and `smstype`. Map the attempt's stable idempotency key to `msgid` with a documented length/character rule. Validate Ghana/international destination format with account configuration. A 200 `ACCEPTD` is queued. Store a provider message ID/reference and update status from authenticated callback only after FROG confirms a trust mechanism. Before that confirmation, callback data is advisory and cannot cause irreversible user-facing decisions. On network timeout, avoid automatic duplicate sends until repeated-`msgid` behavior is confirmed; retain the attempt for operator reconciliation. See [send](https://frogdocs.wigal.com.gh/send_general.html) and [callback](https://frogdocs.wigal.com.gh/callback.html).

## 7. Schema and migration sequence

Use forward-only module-band migrations, allocated at implementation time. Proposed sequence:

1. Platform selection table with four rows, explicit safe defaults by environment. Production payment default `disabled`; no implicit row = disabled. Preserve existing rail flags.
2. Payments vendor columns, nullable only during backfill. Classify and resolve active historical rows before enforcing non-null for new work. Never change an already merged migration.
3. Media location/store code plus a migration checkpoint/manifest owned by media. Classify current assets as MinIO only if deployment evidence confirms their true location. In production with unknown location, pause migration and preserve old reads.
4. Notifications delivery-attempt provider code and provider message/reference fields. Existing attempts are assigned to their actual configured local transport only after checking deployment history; unknown pending attempts need operator review.
5. Identity email send tracking only if the chosen delivery model needs persistence. Keep token storage and expiry unchanged unless the relevant identity ADD and tests explicitly require a change.

No cross-module foreign keys. Idempotency and deduplication constraints must exist at the owning table, not only in application code. Large object copies run outside Flyway; Flyway adds schema and safe metadata backfills only. Each DDL migration applies to empty and existing Postgres instances.

## 8. Configuration and security

The existing [application.properties](../../../backend/src/main/resources/application.properties) and [Compose stack](../../../backend/docker-compose.yml) remain the configuration anchors. The Resend API key and sender may be entered in the super-admin UI and stored in the provider runtime-config table, separate from provider-selection rows. Encrypt configuration with AES-256-GCM using a base64 32-byte `BEATZ_PROVIDER_CONFIG_ENCRYPTION_KEY` supplied by the deployment secret store. Never return key material, include it in audit payloads/logs, or place it in frontend Vite configuration, mobile builds, or Graphify output. Back up the encryption key per environment; losing it makes saved credentials unreadable. SMTP/Mailpit remains the local default. Validate selected provider readiness at activation and at startup, while allowing the service to boot in a safe disabled/degraded mode so old reconciliation can continue when one new provider is misconfigured.

Provider callback routes have separate trust models: Resend verifies raw-body signature; Redde confirms by authenticated status pull; FROG authenticity awaits vendor confirmation. Log correlation IDs and provider code, not payloads containing PII. Enforce small request body limits on callbacks and rate limits where appropriate. TLS and least-privilege credentials are production requirements.

## 9. Rollout and rollback

Deploy schema and provider-aware reads first, then write-side selection, then each real adapter. Default to current local providers and production payment `disabled` until readiness evidence exists. Activate one capability at a time. A provider switch does not migrate assets or pending operations automatically. Before an S4 cutover, inventory all keys and run a copy dry run. Before Redde activation, run merchant sandbox charge/cashout and webhook tests, verify public callback URLs, and check no ambiguous nonterminal records. To roll back new work, select `disabled` or the prior provider for **new** operations; leave recorded-provider workers running. To roll back media, use the retained source location manifest and copied source objects.

Required evidence: empty-DB migration, existing-DB migration, unit/IT/contract/ArchUnit/coverage/Spotless gates, Compose smoke, browser playback, provider sandbox fixture results, and a written operator cutover checklist. Use [testing strategy](../../../backend/docs/sdlc/testing-strategy.md) and [SDLC playbook](../../../backend/docs/sdlc/agent-workflow.md).
